An entity ​

So far every value has been local: it lives in a variable, and it's gone when the function returns. Real programs keep state: stock on a shelf, a user's settings, the phase of a game world. In Eyelang, shared state lives in entities. An entity has an identity, state that only it can change, and methods that change it one transaction at a time.

The program is docs/tutorial/code/an-entity/main.eye.

Open it in the playground to run it, test it and change it in your browser.

A shelf ​

Each item in the shop has a shelf: how many are in stock, and how many each order is holding.

eye
type StockError = | OutOfStock(left: Int)
eye
entity Shelf(item: String) {
  state count: Int = 0
  state held: Map(String, Int) = {}

  pub fn restock(n: Int) { count += n }

  pub fn hold(order: String, n: Int) -> Result((), StockError) {
    if n > count { return Err(OutOfStock(left: count)) }
    count -= n
    held = held |> insert(order, n)
    Ok(())
  }

  pub fn release(order: String) {
    let n = held[order] ?? 0
    count += n
    held = held |> remove(order)
  }
}
  • entity Shelf(item: String) declares the entity and its identity. Shelf("apples") and Shelf("pears") are two different shelves.
  • state count: Int = 0 is a field of the entity's state, with the value a new shelf starts with.
  • pub fn declares a method that code outside the entity can call. Inside a method, the state fields are variables: count -= n changes the shelf's count.

Using it ​

eye
test "an entity keeps its state between calls" {
  let apples = Shelf("apples")
  expect(apples.count == 0)
  apples.restock(5)
  expect(apples.hold("order-1", 3) == Ok(()))
  expect(apples.count == 2)
  expect(apples.hold("order-2", 3) == Err(OutOfStock(left: 2)))
  apples.release("order-1")
  expect(apples.count == 5)
}

Shelf("apples") doesn't create anything. It names the shelf whose identity is "apples". An entity exists from its first use, with the state's defaults, so there is no "create" step and no "not found" case.

Reading a field, apples.count, reads the current state. Calling a method, apples.hold(...), runs it against the state and saves the result.

eye
test "the same id is the same entity" {
  Shelf("pears").restock(4)
  expect(Shelf("pears").count == 4)
  expect(Shelf("plums").count == 0)
}

Methods are transactions ​

Each method call is one transaction: one writer at a time per entity, all or nothing. While hold runs, nothing else can change the same shelf. So hold can check the count and then take from it without a race: no other order can take the last apple between the check and the change. Nothing outside the method sees a change until the call is done.

You don't write locks for this, and you can't forget one. The state belongs to the entity, and the only way to change it is through its methods.

Methods can't wait. A method that called sleep! would hold the shelf for as long as it slept, so the checker refuses it:

text
main.eye:13:5: an entity method is a transaction and can't wait; start a job for this instead

Waiting is what jobs are for. The next page starts one from a method.

References ​

Ref(Shelf) is the type of a reference to a shelf. A reference is an identity, not a pointer: it can be stored in a record or a list, sent, and saved, and it always means the same shelf.

eye
type Line = { shelf: Ref(Shelf), n: Int }

fn holdAll(order: String, lines: List(Line)) -> List(String) {
  var short = []
  for line in lines {
    match line.shelf.hold(order, line.n) {
      Ok(_) => ()
      Err(OutOfStock(_)) => short += [line.shelf.item]
    }
  }
  short
}

holdAll takes an order's lines and holds each one, collecting the items that are short. line.shelf.hold(...) calls a method through the stored reference, and line.shelf.item reads the shelf's identity.

eye
test "a Ref names an entity, and can be stored" {
  Shelf("milk").restock(2)
  Shelf("bread").restock(1)
  let lines: List(Line) = [
    { shelf: Shelf("milk"), n: 1 },
    { shelf: Shelf("bread"), n: 2 },
  ]
  expect(holdAll("order-7", lines) == ["bread"])
  expect(Shelf("milk").count == 1)
  let snapshot = Shelf("milk").read()
  expect(snapshot.held == { "order-7": 1 })
  expect(snapshot.version == 2)
}

read() returns a snapshot of the entity: its identity, its state, and a version that counts the transactions that changed it. A snapshot is a plain value. It doesn't change when the entity does, so it's what you pass to code that should look but not touch.

Every shelf ​

Shelf.all is every shelf there is, as a collection, so the usual pipes work on it:

eye
test "Shelf.all lists every shelf" {
  Shelf("tea").restock(3)
  Shelf("jam").restock(0)
  let stocked = Shelf.all |> filter(fn s: s.count > 0) |> map(fn s: s.item)
  expect(stocked == ["tea"])
}

A program that needs such a list often, such as "every shelf that is running low", declares a view: a query the runtime keeps up to date as transactions commit, and that can start a job whenever an entity enters it.
