Effects and signatures ​

The compiler infers what each function touches. Public signatures state it with uses, so a new permission always shows up in the diff.

eye
pub fn summarise(items: List(Item)) -> String uses {wait, net Llm.complete} {
  llm.complete!(prompt(items))
}
EffectComes fromWhat the compiler does with it
waitany ! call, and a call of a function that waits, such as sleep(1 s) outside a jobCompiles the function to a resumable state machine; see waiting functions below

Every effect in the table is inferred, and a private function's effects never need writing. A public function that publishes an event, reads a secret, starts a job or calls an extern fn lists it in uses as the table names it, as one that calls a service lists net C.op: uses {publish Bus.pinged}, uses {secret "telegram-bot-token"}, with the name as passed to secret(…), uses {start digest}, with the job's name, and uses {ffi}. A bare kind covers all of its kind: net every operation, publish and consume every event, entity every entity, start every job, and secret every secret, which is what reading a secret by a name that isn't a literal needs. An extern fn that states its own uses, as http.get states net Http.get, has those effects instead of ffi.

  • Pure means no uses. A public function without a uses clause is pure, and the compiler holds it to that: if area read a file, the error would say area uses fs, which its signature doesn't list: run eye fmt, or add uses {fs}. Editors show the inferred effects of private functions.

  • Public entity methods and jobs state theirs too. A pub fn in an entity and a pub job are boundaries like any public function: pub fn join(p: PlayerId) uses {start wake} in the tour, and a pub job lists everything it does, wait included. What a method does to its own entity's state isn't an effect; calling another entity's method is entity E.

  • eye fmt writes the clauses. Formatting a program's directory, eye fmt DIR, checks the program and writes each public function's, entity method's and job's uses from what its body does: it adds a missing effect and drops one the body no longer has. An entry that still covers an effect stays, as net stays while the body calls any service; a clause that changes is written in sorted order. A file formatted alone (eye fmt FILE, or an editor formatting on save) is formatted for syntax only, and so is a program with other errors, which eye fmt reports. A private function's clause is a limit its author sets, so eye fmt leaves it as written.

  • Callbacks pass their effects to the call. A function that takes a function lists only its own effects; calling it adds the effects of the function passed in, where the call is written. map is pure, and paths |> map(fs.readText) uses fs:

    eye
    import fs

pub fn missing(paths: List(String)) -> List(String) uses {fs} =
  paths |> filter(fn p: !fs.exists(p))    # fs comes from the lambda, not from filter

    So retry, timeout, race, parallelMap and reserve! work with any function, and every public signature still lists everything its body can do. A callback can't outlive the call, so a lambda given as one may also read a var or a mut parameter, as its value at the call (section 7).

  • Functions stored in data state their effects. A function type without uses is pure, except in a parameter's type, where it takes a callback (below). One kept in a field or a collection, and called later, says what it may do:

    eye
    type Handler = { name: String, run: fn(Event) uses {net Notify.send} }

    In a function's return type, the uses after a function type belongs to that function type.

    Whoever calls a stored function later counts only what its type states, so a function kept there may do no more: { name: "n", run: fn e: now() } is an error, this function uses clock, which its type here, fn(Event) uses {net Notify.send}, doesn't list. The same holds for a lambda or a named function put in a list, returned, or passed where a parameter's function type has a uses clause, which is then a limit. A function type without uses anywhere in a parameter's type, as in map's fn(a) -> b or inside race's List(fn() -> a), takes a callback, which may do anything (the parameters and result of that function type keep the general rule); so a callback can't be kept in data, nor can a lambda that calls one. To keep it, state its effects in the parameter's type: fn register(run: fn(Event) uses {clock}) -> Handler. A stored function given as a callback, as in xs |> map(h.run), does what its type states, which counts where it is given.

! in jobs. Inside a job, ! marks every recorded step: it runs once and its result is recorded, so a resumed run never repeats it and sees the same values. The steps are:

  • every call with an outside effect (net, fs, process, clock, random, env, ffi, secret, entity, publish and start), an extern fn included (open!(path)). That holds for a function of the program too: stamp!(), where fn stamp() = now(), is one step, and calling it without ! is an error, in a job, stamp uses clock, so calling it is a durable step: write stamp!(…);
  • entity calls (w.read!(), w.markAsleep!()), each committed in the same transaction as its checkpoint (section 15), and reading a view or every entity of a type, idleWorlds.read!() and World.all.read!();
  • publishing an event, bus.pinged.publish!({ n: 1 }), which is sent when the step commits;
  • starting a child run, digest.start!(day), so a resumed run doesn't start it again.

Calls that only compute are ordinary, and ! on one is an error. Outside jobs the same functions are called without !: in main (section 13) and in tests. Entity methods and served operations can't make most of these calls at all: they are transactions, which stay inside the program (section 14). Output is not a step: print has the effect stdio, which public signatures list, but in a job it is written without ! and isn't recorded, and logging (log.info) is not an effect at all. Output is for people watching a run, not part of what the run computes.

Waiting functions. A function whose body has ! steps, such as summarise above, is a waiting function. It has wait in its effects, and a job calls it with !: its steps are recorded as the job's own, and replayed with them (section 15). So it follows a job's rules for steps: every wait, every call with an outside effect, an entity call, publishing, starting a child run and reading entities or views is a ! step in it, a call that only computes isn't, and a task it starts only computes. Written without !, such a call would run again each time the run replays the function, so it is an error that says where: in a waiting function, env.get uses env, so calling it is a durable step: write env.get!(…), in a waiting function, an entity call is a durable step: write bump!(…). Its variables, parameters included, are part of the run's saved state as a job's are, so one that holds what can't be saved, such as a Secret, can't be live across a ! in it (section 15). main is not a waiting function, whatever it calls. Only a run records steps, so neither main nor a test can call a waiting function, with ! or without: summarise has durable steps, which only a job records, so main can't call it: start a job that does.

  • Outside a job, a wait blocks. sleep(1 s), sleepUntil(…) and poll(…), written without ! in main, a test or a plain function, hold the caller until they return; in a test they move the test's clock. They still wait, and so does a function that calls one, so the call keeps wait in the caller's effects: pub fn pause() uses {wait} { sleep(1 s) }. A job can't call such a function, with ! or without, since the run couldn't record its wait: pause waits through calls without !, which block outside a job, so a run couldn't record its wait: write the waiting calls in pause with !, as sleep!(…). next, approval and reserve wait for what only a run can wait for, so outside jobs and waiting functions they are errors.

A step's result is saved. It is recorded so that a resumed run sees the same value, so it must be something that can be saved (section 15). A Secret, or a value of an extern type, is used inside a function that returns what can be saved, and that function is called as one step: checksum!(path) rather than open!(path) followed by more calls on the handle. An error says so: this durable step's result is recorded, and a Secret can't be saved: use it in a function that returns what can be, and call that with !.

eye
import bus

job ping(day: Date) {
  bus.pinged.publish!({ n: 1 })              # a step: published when it commits
  let child = digest.start!(day)             # a step: a resumed run doesn't start it twice
  log.info("started {day}")                  # not a step
  sleep!(1 min)
}
