Language reference ​

Eyelang 2 is a general-purpose, statically typed, compiled language for software that keeps state and waits: services, automations, schedulers and agents that run for days, wait for people, hold data, call other services that fail, and spend most of their time waiting. It lets you write such a program as plainly as a script, and its compiler catches the mistakes such programs usually ship with. Typically that means data spread across many entities (users, devices, game worlds, apps) and jobs that run briefly and then wait for minutes, hours or days. It is not a configuration DSL: every feature below is an ordinary language construct that also works outside that domain. Section 1 lists what the language promises and the principles it is designed by.

Glossary ​

Words this document uses in one sense, and names that mean different things in different places.

WordMeaning
runOne execution of a job, from its start to its outcome. Each start makes one, unless its key started one already; Run(a) is the value that names it (section 15).
stepA ! call in a job. It runs once, and its result is recorded in the run, so a resumed run gets the recorded result instead of calling again (section 12).
checkpointA run's saved place: its live variables, the statement it is at, and where each loop around it is. The interpreter takes one at a statement of the job's body once steps have been taken since the last; a run that wakes restores the latest and replays only the steps since (section 15). zeropod.checkpoint! in the tour is an operation of a service, not this.
transactionWhat runs all or nothing: an entity method's call tree, a served operation, or a job's step that calls an entity. Jobs it starts and events it publishes happen only if it commits (section 14).
keyAn idempotency key, a Key: what tells one command, job start or event from a repeat of it, so the same key never does the work twice (key: on a call, @key on an operation or event). A map's keys are ordinary values.
versionA snapshot's version is a Version that counts the transactions that changed the entity, and is what a @fresh command's basedOn takes (sections 14 and 17). @version(N) numbers the shape of an entity's stored state, for migrations. A state field can't be named version.
handlerWhat with applies to the rest of a test's block: clock(…), of the built-in type Handler, and fakes(…), of the built-in type Fakes, which also lists the calls it answered (section 20). A program may declare its own Handler, as section 12's example does; in its module the name is the program's.
outcomeA run's Outcome, Completed(value) or Failed(fault) (section 15); a command's outcome is the variant its result is (section 17).
faultWhat ends a run that code can't catch, such as DeadlinePassed or Unreachable (section 15). An Err is a value, not a fault.
methodWhat x.f(a) calls: a method of x's type, from its impl, an entity's or a trait's; else a field of x that holds a function; else a function in scope whose first parameter takes x, as f(x, a) (section 8).
callbackA function given to a parameter whose function type has no uses, as filter's. It can't be kept, so it runs before the call returns: its effects count where it is given (section 12), and a lambda given as one may read a var (section 7).
endIn an entity's own method, end(ok) ends the entity (section 14). Elsewhere s.end() is a string's end position, and r.end a range's end.
startj.start(…) starts a run of job j, and claude.start!(…) an agent's session. s.start() is a string's first position, and r.start a range's start.
firstfirst(xs) is a collection's first element, an Option. Waiting for whichever of several runs finishes first is firstDone!, and for all of them allDone!, named apart from first and all (section 15).
joinxs |> join(", ") joins strings; run.join!() waits for a run's outcome, in a job. A test or main reads the outcome without waiting, with run.outcome(), and run.join() on a run is an error that says so.
